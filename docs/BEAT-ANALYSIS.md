# Local BPM and beat-anchor assistant

`analyzeBeats(Float32Array, sampleRate, options)` consumes decoded local PCM only. It does not fetch YouTube audio or send PCM to AI. The review UI uses the first audio channel, explicitly disclosed; for a track with percussion exclusively on another channel, provide a mono mix.

The original dependency-free algorithm computes positive changes of 5 ms RMS-energy bins, normalized lag autocorrelation in up to 24 evenly spaced 20-second windows, local lag peaks and periodic onset phase. Default range 40–240 BPM; silence and insufficient evidence return no candidates. This is an aid, not a robust full-mix beat tracker: swing, syncopation, sustained sounds and changing tempo can confuse it. Confidence is a heuristic periodicity score, not a probability. `basis` distinguishes measured periodicity from explicitly derived half/double-time alternatives. Section candidates expose local hypotheses without claiming exact tempo-change boundaries. No meter/downbeat inference is performed.

`beatOffsetSeconds` is a candidate SOURCE-audio beat, not necessarily the first beat/downbeat. It must be auditioned. Starting offset alone cannot correct later tempo drift. `tempoFromAnchors` uses confirmed musical quarter-note distance and source time distance. `planTempoFromAnchors` requires beat zero and at least one further anchor; each adjacent pair specifies constant BPM, and the last segment continues. Sign: **sourceTime = chartTime + sourceOffsetSeconds**. Native DTX variable bar lengths remain untouched; callers must convert bar positions using the project's persistent `#mmm02` semantics, never assume four beats per bar. The plan returns effective BPM; DTX resource/base-BPM encoding belongs to the codec/integration, not this helper.

Proposals never mutate a project. `openBeatDialog(host)` requires explicit reviewed-anchor checkbox and Apply. It captures the chart revision and refuses stale application. The host must apply the plan transactionally, retain bar lengths and notes, and reject unsupported effective BPM or read-only projects. The UI explicitly warns that the existing tempo map is replaced. Source decode is not browser-abortable, but analysis results are discarded on cancellation/close; the AudioContext is closed.

Bounds: default 30 minutes, hard 60 minutes, 200 million input samples, 24 analysis windows, 200 Hz envelope, 30-second default time budget (maximum 120 seconds). UI adds a 100 MB file cap before browser decoding. Long files may require a short excerpt because decoded PCM limits are intentionally strict. Energy scanning yields every 5 seconds of audio; correlation yields each bounded window. AbortSignal and timeout are checked between chunks. Moving analysis to a Web Worker is recommended for future lower-end-device hard latency guarantees; browser decoding and one correlation window cannot be interrupted mid-operation. Gaps between sampled windows can hide tempo changes.

Tests cover 90/120/180 BPM click tracks, phase offsets, quiet/silent/short inputs, section changes, swing/offbeats, ambiguity, nonfinite data, limits, timeout, cancellation, anchor arithmetic and invalid anchors. Real full-mix accuracy still needs user audition; tests are not a general accuracy benchmark.

DOM integration tests (`beat-ui.test.ts`, happy-dom) exercise opening without mutation, mandatory confirmation, edited 120→180 anchors with +0.25 offset, stale revision rejection, invalid order, source audition, missing source and closing during decode. These are not physical-browser audio/hardware acceptance tests.
