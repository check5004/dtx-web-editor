## Platform limits (not missing native-code ports)

- GitHub Pages is static: local folder access requires user selection/permission; browser storage is origin-specific and can be cleared or exhausted. Always export a project archive.
- Web MIDI requires a supported browser, secure context and explicit permission. Device names are not unique stable identities. No automatic cross-device mapping is assumed.
- YouTube uses the official iframe API, not decoded audio. No waveform/BPM extraction from YouTube, no download; embedding, ads, buffering and player timing constrain synchronization.
- Browser audio/video decoding depends on codec support. Local analysis is capped/yielding and cancellable between work chunks; decoding itself is not fully abortable. See the analysis guide for limits.
- Native NX load/play and device audio latency cannot be proven by JavaScript unit tests. Arbitrary legacy/branch constructs are preserved safely rather than falsely advertised as supported editable semantics.

## Release gates and remaining scope

1. Run `npm test` and `npm run build`; record their actual results in release evidence, not a stale hard-coded suite count here.
2. Exercise each integrated control in a real browser, including error/Undo/Redo, original-source backup, archive restoration, protected files, narrow screens and audio listening. Source inspection alone is insufficient.
3. Load exported CP932 packages in Windows DTXManiaNX and verify four-cymbal drums, changing BPM/bar lengths, guitar/bass, BGM and media. **Native gameplay validation has not been performed in this environment.**
4. Verify physical MIDI hardware and mode/channel/HH pedal behavior before publishing device-specific presets.
5. Complete browser/native acceptance of integrated long-note/voice, palette setup, full channel groups and reusable library workflows before claiming verified equivalence across all old Creator behaviors. Implemented controls alone do not prove behavioral equivalence.
