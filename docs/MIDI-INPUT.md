# 電子ドラム / Web MIDI 入力

MIDI ファイルの読み込みと、USB / MIDI 機器のリアルタイム入力は別機能です。Web MIDI の接続ボタンを押したときだけ `requestMIDIAccess({sysex:false})` を呼びます。HTTPS / 対応ブラウザと利用者の許可が必要です。接続拒否・非対応ではキーボードや MIDI ファイル入力を引き続き利用できます。

## 機器とモード

入力ポートを明示的に選び、機器 / モード別プロファイルを作成します。保存する識別情報は port ID、表示名、メーカー名ですが、名前による自動再割り当てはしません。同名機器が複数ある場合にも入力を混ぜません。再接続、ブラウザ変更、モード変更では割り当てを確認してください。ブラウザ起動時の自動権限要求はありません。

CH は UI / 設定 JSON とも **1〜16**、ノート / CC は **0〜127** です。MIDI ステータスの下位 4 bit（0〜15）とは表記が異なります。各機器は同時に一つのモードを使用します。

新規設定は汎用 GM の編集用候補であり、Roland / Yamaha など特定の実機での正しさを保証するプリセットではありません。WAV ID は現在の曲の音源 ID に合わせてください。

## 学習と HH

1. 入力機器とプロファイルを選択。
2. DTX チャンネル、WAV ID、打面名を入力し「次の打撃を学習」。同じ機器 / CH / ノートを更新し、別ノートの bow / edge / bell を保持します。
3. ペダル式 HH は打面の HH 切替を有効化。ペダルを CC 学習し、完全オープン / 完全クローズの値を校正します。
4. 詳細 JSON で `openMax` / `closedMin` / `hysteresis` / `invert` を調整。スイッチの 0 / 127 と連続 CC の両方に対応します。ペダルの入力 CH は打面と異なっても設定可能です。他の CH / CC / 機器のペダル状態は混入しません。
5. `hiHat.closed` / `open` / 任意の `halfOpen` の WAV を選びます。DTX HH は `11` / `18` のみです。半開き専用 DTX チャンネルは作りません。

最初の CC、切断後、モード変更後、古い状態（既定 10 秒）ではペダルの状態を推測しません。未確定時は打面の通常 target を使用します。保持し続けるペダルの CC を再送しない機器では `staleMs` を長く設定できます。

`footClose` / `splash` は既定で無効です。実機が足ノートを送るならそのノートを割り当て、CC 合成を重複させないでください。CC 合成は既知の完全オープンからクローズへの遷移を要求し、しきい値付近の揺れや最初の値では足音を生成しません。スプラッシュには `splashWindowMs` 内の再オープンが必要です。

学習中は**全入力の録音 / 試聴を抑止**します。ノートオフ、velocity 0 のノートオンは打撃になりません。学習終了後は試聴で確認してから MIDI 録音を有効化します。

## 録音の組み込み

`createMidiUI({show,close,onHit,toast})` の `onHit(hit,record)` は実際の transport が再生中か別途確認してください。未録音は試聴のみです。`recordingBeat` へ受信イベントの `timeStamp` と、同じ `performance.now()` 時点の実際の transport 時刻、再生速度、入力遅延 ms、テンポマップの secondsToBeat、クオンタイズ関数を渡します。正の入力遅延は記録位置を早めます。音声出力の遅延設定とは分けて扱います。シーク / ループの境界を跨ぐ古いイベントはホスト側でも破棄してください。

ダイアログを閉じても接続は保持します。「切断」で入力を止めます。設定変更・学習で録音は OFF に戻ります。ホストは対象 WAV の存在や同位置重複、読み取り専用の保護を行ってください。

## 保存と検証

プロファイルはブラウザ localStorage。JSON はバージョン 1、機器 / モード / 打面 / ペダル設定のみ。API キーや音声データは含めません。破損・未知バージョン・範囲外値・重複マッピングを拒否します。明示的な旧 v0 エンベロープは同形設定のみ v1 として読み込めます。

単体テストは擬似入力で、同名機器・同 CH、モード変更、CH 1 / 16、ノートオン 0、ペダル反転 / ヒステリシス / stale / 切断、学習抑止、保存 / 移行、受信タイムスタンプを検証します。**物理 MIDI 機器の接続と機種固有 CC 動作は未検証です。**

実装の API 参照: [W3C Web MIDI API](https://www.w3.org/TR/webmidi/)（権限、入力ポート、MIDIMessageEvent）。
